FIT4US V1.2 PRIVATE – SCHRITT-FÜR-SCHRITT ONLINE
====================================================

ZIEL
----
GitHub Pages hostet die Website.
Supabase übernimmt Login, zentrale Datenbank, Bilder, Realtime und Zugriffsregeln.

Neue Konten sind standardmäßig GESPERRT.
Nur ein Fit4Us-Admin kann sie in der App freischalten.
Ohne Freigabe sieht ein neuer Benutzer ausschließlich die Warteseite.

====================================================
TEIL A – SUPABASE EINRICHTEN
====================================================

1. SUPABASE-PROJEKT ANLEGEN
---------------------------
1. Öffne https://supabase.com/
2. Anmelden / Account erstellen.
3. "New project" wählen.
4. Organisation auswählen oder eine anlegen.
5. Projektname z. B. "fit4us".
6. Ein starkes Datenbank-Passwort vergeben und sicher aufbewahren.
7. Region möglichst in Europa auswählen.
8. Projekt erstellen und warten, bis es vollständig bereit ist.

2. DATENBANKSCHEMA INSTALLIEREN
------------------------------
1. Im Supabase-Projekt links "SQL Editor" öffnen.
2. "New query" / neue Abfrage erstellen.
3. Die Datei "supabase-setup.sql" aus diesem ZIP öffnen.
4. Den GESAMTEN Inhalt kopieren.
5. Im SQL Editor einfügen.
6. "Run" ausführen.
7. Es dürfen keine roten Fehlermeldungen übrig bleiben.

Dadurch werden erstellt:
- profiles
- entries
- reactions
- weekly_challenges
- reward_choices
- private Storage-Buckets avatars + proofs
- Row Level Security
- Freischaltungslogik
- Admin-RPC
- Realtime

3. E-MAIL-BESTÄTIGUNG DEAKTIVIEREN
-----------------------------------
Fit4Us verwendet für den Nutzer sichtbar nur Benutzername + Passwort.

Supabase Auth arbeitet intern mit E-Mail/Passwort. Fit4Us erzeugt deshalb
eine technische Adresse aus dem Benutzernamen.

1. In Supabase zu Authentication wechseln.
2. Providers / Sign In / Email öffnen.
3. Email + Password aktiviert lassen.
4. "Confirm email" / E-Mail-Bestätigung DEAKTIVIEREN.
5. Speichern.

Der Nutzer bekommt in Fit4Us niemals diese technische Adresse zu sehen.

4. PROJECT URL + KEY HOLEN
--------------------------
1. Supabase → Project Settings / Settings.
2. Bereich API öffnen.
3. Project URL kopieren.
4. Den publishable key bzw. anon/public key kopieren.

WICHTIG:
- Publishable/anon Key darf im Webfrontend stehen.
- NIEMALS service_role / secret key in GitHub oder config.js eintragen.

5. CONFIG.JS BEFÜLLEN
---------------------
Im Fit4Us-Ordner die Datei "config.js" öffnen.

Ersetzen:

supabaseUrl: "DEINE_SUPABASE_PROJECT_URL"

durch z. B.

supabaseUrl: "https://abcdefgh.supabase.co"

und

supabaseKey: "DEIN_SUPABASE_PUBLISHABLE_ODER_ANON_KEY"

durch deinen echten Publishable-/Anon-Key.

Datei speichern.

====================================================
TEIL B – GITHUB EINRICHTEN
====================================================

6. GITHUB-REPOSITORY ERSTELLEN
------------------------------
1. https://github.com/ öffnen und anmelden.
2. Rechts oben "+" → "New repository".
3. Name z. B. "fit4us".
4. Repository erstellen.

ACHTUNG:
GitHub Pages ist eine öffentlich erreichbare Website.
Auch wenn dein Repository je nach GitHub-Tarif privat sein kann, darfst du
KEINE geheimen Schlüssel oder Passwörter in den Dateien speichern.

Der Supabase publishable/anon Key ist hierfür vorgesehen.
Der service_role Key ist es NICHT.

7. FIT4US-DATEIEN HOCHLADEN
---------------------------
Diese Dateien müssen direkt im Repository-Root liegen:

index.html
style.css
app.js
config.js
supabase-setup.sql
manifest.webmanifest
sw.js
.nojekyll
README.txt
assets/

Auf GitHub:
1. "Add file" → "Upload files".
2. Alle Dateien und den Ordner assets hochladen.
3. Commit message z. B. "Fit4Us V1.2".
4. "Commit changes".

Hinweis:
"supabase-setup.sql" enthält keine geheimen Daten und darf im Repository liegen.
Wenn du möchtest, kannst du sie nach erfolgreicher Einrichtung trotzdem später entfernen.

8. GITHUB PAGES AKTIVIEREN
--------------------------
1. Repository → "Settings".
2. Links "Pages".
3. Unter "Build and deployment":
   Source = "Deploy from a branch".
4. Branch = "main".
5. Folder = "/ (root)".
6. "Save".

GitHub veröffentlicht die Seite anschließend.
Die Adresse ist normalerweise:

https://DEIN-GITHUB-NAME.github.io/fit4us/

Es kann einige Minuten dauern.

====================================================
TEIL C – ERSTEN ADMIN ERSTELLEN
====================================================

9. DEIN KONTO REGISTRIEREN
--------------------------
1. GitHub-Pages-Adresse öffnen.
2. "Konto erstellen".
3. Benutzername festlegen.
4. Vorname eingeben.
5. Nachname eingeben.
6. Passwort festlegen.
7. Registrieren.

Du landest nun ABSICHTLICH auf:
"Freischaltung ausstehend"

Das ist korrekt.

10. DICH EINMALIG ZUM ADMIN MACHEN
----------------------------------
1. Wieder Supabase öffnen.
2. SQL Editor.
3. Neue Query.

Folgendes ausführen, wobei du deinen echten Login-Benutzernamen einsetzt:

update public.profiles
set is_admin=true,
    approved=true,
    approved_at=now()
where username='DEIN_BENUTZERNAME';

Beispiel:
where username='adrian';

4. Fit4Us-Seite neu laden oder "Status prüfen" drücken.

Jetzt bist du freigeschaltet und siehst als Admin den Menüpunkt "Admin".

====================================================
TEIL D – DIE ANDEREN 3 FREISCHALTEN
====================================================

11. Tabea / Marcel / Lena registrieren sich
-------------------------------------------
Jeder öffnet Fit4Us auf seinem eigenen Gerät und erstellt sein eigenes Konto.

Jeder wählt:
- eigenen Login-Benutzernamen
- Vorname
- Nachname
- eigenes Passwort

Danach sehen sie zunächst "Freischaltung ausstehend".

12. DU SCHALTEST SIE FREI
-------------------------
1. Mit deinem Admin-Konto in Fit4Us anmelden.
2. "Admin" öffnen.
3. Unter "Offene Registrierungen" erscheint der neue Account.
4. "Freischalten" drücken.

Der andere Nutzer drückt danach auf "Status prüfen" oder lädt die Seite neu.

Ab jetzt hat er Zugriff.

Du kannst den Zugriff später im Adminbereich wieder sperren.

====================================================
WICHTIGE SICHERHEITSHINWEISE
====================================================

- Kein service_role Key in GitHub.
- Keine privaten Passwörter in Dateien.
- GitHub Pages selbst ist öffentlich erreichbar.
- Die Fit4Us-DATEN sind trotzdem durch Supabase Auth + RLS geschützt.
- Nicht freigegebene Accounts sehen keine Gruppe.
- Normale Nutzer können nur eigene Einträge ändern/löschen.
- Der Admin kann Accounts freischalten/sperren.
- Passwörter werden durch Supabase Auth verwaltet, nicht durch Fit4Us gespeichert.

====================================================
UPDATES SPÄTER
====================================================

Wenn eine neue Fit4Us-Version kommt:
1. Neue Dateien ins GitHub-Repository hochladen/ersetzen.
2. Commit.
3. GitHub Pages veröffentlicht automatisch neu.
4. Falls sich das Datenbankschema ändert, liefere ich zusätzlich ein SQL-Migrationsskript.
5. Bei PWA-Cache-Problemen ggf. die Seite hart neu laden bzw. Website-Daten löschen.

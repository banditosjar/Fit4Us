FIT4US V1.3 – UPDATE EINER BESTEHENDEN ONLINE-INSTALLATION
================================================================

WICHTIG:
Deine Nutzerdaten liegen in Supabase, NICHT in den GitHub-Dateien.
Beim Austausch von HTML/CSS/JavaScript gehen deshalb keine bestehenden
Benutzer, Aktivitäten, Fotos, Rankings oder Reaktionen verloren.

VOR DEM UPDATE
--------------
1. In GitHub dein Fit4Us-Repository öffnen.
2. Deine bestehende "config.js" NICHT löschen und NICHT überschreiben.
   Darin stehen deine Supabase Project URL und dein Publishable/Anon Key.

DATENBANK-MIGRATION
-------------------
3. Supabase öffnen → SQL Editor → New Query.
4. Datei "MIGRATION_V1_3.sql" öffnen.
5. Inhalt vollständig einfügen und "Run" drücken.

Diese Migration löscht KEINE Daten.
Sie setzt lediglich für die aktuelle Woche 17.–23.08.2026 die Challenge
"Draußenzeit". Danach wählt jeweils der Gewinner der Vorwoche.

WEBSITE-DATEIEN AKTUALISIEREN
-----------------------------
6. Aus dem ZIP "Fit4Us_v1_3_UPDATE.zip" folgende Dateien auf GitHub
   hochladen und die alten Versionen ersetzen:
   - index.html
   - style.css
   - app.js
   - manifest.webmanifest
   - sw.js
   - assets/ (falls GitHub danach fragt: Dateien ersetzen)
   - .nojekyll kann unverändert bleiben.

7. "config.js" bleibt die bereits vorhandene Datei im Repository.
   Das UPDATE-ZIP enthält sie absichtlich NICHT.

8. Commit durchführen, z. B.:
   "Update Fit4Us auf V1.3"

9. GitHub Pages veröffentlicht das Update automatisch.
   Normalerweise nach kurzer Zeit.

NACH DEM UPDATE
---------------
10. https://banditosjar.github.io/Fit4Us/ öffnen.
11. Einmal neu laden.
12. Falls auf einem Gerät noch die alte PWA-Version erscheint:
    - Browser komplett schließen und neu öffnen,
    - Seite erneut laden,
    - notfalls Website-/PWA-Cache löschen bzw. die installierte PWA einmal
      entfernen und neu zum Home-Bildschirm hinzufügen.

DIE SUPABASE-DATENBANK NICHT NEU AUFSETZEN!
-------------------------------------------
"supabase-setup.sql" ist nur für eine komplette Neuinstallation gedacht.
Bei einem bestehenden Projekt für V1.3 ausschließlich "MIGRATION_V1_3.sql"
verwenden.

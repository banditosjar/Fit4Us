Fit4Us V1.16.4 – Auth Stability Hotfix
========================================
Keine Supabase-Migration nötig.
Keine Edge Function neu deployen.

BEHOBEN
- Persistente Session bei „Angemeldet bleiben“ bleibt bestehen.
- TOKEN_REFRESHED startet keinen vollständigen App-Boot mehr.
- Gleichzeitige App-Boots werden dedupliziert.
- Ein kurzzeitiger Profil-/Netzwerkfehler führt NICHT mehr zu automatischem Logout.
- Eigenes Profil wird beim Start automatisch mehrfach versucht.
- Bei Ladeproblemen bleibt die Session bestehen; „Erneut laden“ statt Logout.
- App-Daten werden nur ersetzt, wenn ALLE Datenabfragen erfolgreich waren.
- Teilfehler können Profilbild, Punkte, Feed usw. nicht mehr durch leere Daten ersetzen.
- Realtime-Refresh behält bei Fehler die zuletzt korrekt geladenen Daten.

URSACHE
1. Auth-Events inklusive Token-Refresh konnten parallele App-Boots auslösen.
2. bootApp() hat bei einem einzigen fehlgeschlagenen Profilabruf sofort signOut() ausgeführt.
3. loadData() prüfte nur profiles auf Fehler; andere fehlgeschlagene Requests wurden als leere Arrays übernommen.

UPDATE
1. UPDATE-Dateien nach GitHub übernehmen.
2. config.js NICHT überschreiben.
3. Keine SQL-Migration.
4. Keine Edge Function neu deployen.
